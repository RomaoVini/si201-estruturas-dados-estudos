1. A base: memória, ponteiros e structs

Antes de qualquer estrutura, precisamos estar 100% confortáveis com quatro coisas: variável na memória, ponteiro, struct e alocação dinâmica. Se você já domina, leia rápido — mas leia, porque os erros de prova em listas ligadas quase sempre são erros destas quatro coisas.

1.1 Memória: uma rua de casas numeradas

Pense na memória do computador como uma rua enorme, com casas numeradas de 0 em diante. Cada casa guarda um byte. Quando você declara int x = 10;, o compilador reserva 4 casas seguidas e escreve 10 lá dentro. O número da primeira casa é o endereço de x.

   endereço:   1000   1004   1008   1012
             +------+------+------+------+
   memória:  |  10  |  25  |  ??  |  ??  |
             +------+------+------+------+
                x      y

Dois operadores fazem a ponte entre valor e endereço:

  • &x — "o endereço de x" (leia: onde x mora). Vale 1000 no desenho acima.
  • *p — "o conteúdo do endereço guardado em p" (leia: o que mora lá).

1.2 Ponteiro: uma variável que guarda um endereço

Um ponteiro é uma variável normal. A diferença é que o valor que ela guarda é um endereço de memória, e o tipo dela diz o que esperar nesse endereço.

int x = 10;
int *p;      /* p é um ponteiro para int */
p = &x;      /* p passa a guardar o endereço de x */
printf("%d", *p);   /* imprime 10: "vá até o endereço em p e leia" */
*p = 99;    /* escreve 99 DENTRO de x, sem tocar no nome x */

      p                      x
   +------+               +------+
   | 1000 | ------------> |  99  |
   +------+               +------+
   (end. 2000)            (end. 1000)

A seta do desenho é o coração de tudo o que vem depois. Uma lista ligada é só um monte dessas setas encadeadas.

NULL: a seta que não aponta para lugar nenhum

NULL é um valor especial de ponteiro que significa "este ponteiro não aponta para nada válido". Usamos NULL para marcar:

  • o fim de uma lista ligada (o último nó aponta para NULL);
  • uma estrutura vazia (lista/pilha vazia = ponteiro inicial em NULL);
  • uma falha de malloc ou uma busca que não achou nada.
O erro que mais derruba programa

Fazer p->info quando p é NULL. Isso é acessar o endereço 0 → segmentation fault. Regra permanente: antes de usar um ponteiro, garanta que ele não é NULL. Em prova escrita, o professor adora colocar exatamente esse caso (remover de lista vazia, consultar topo de pilha vazia).

1.3 struct: agrupando dados que andam juntos

Uma struct junta várias variáveis sob um nome só. É o que nos deixa dizer "uma pilha é um vetor mais um índice de topo" e tratar os dois como uma coisa só.

struct aluno {
    int ra;
    float nota;
};

struct aluno a;
a.ra = 200123;        /* acesso por variável:  ponto  */

struct aluno *pa = &a;
pa->ra = 200123;      /* acesso por ponteiro:  seta   */
(*pa).ra = 200123;   /* exatamente a mesma coisa que a linha acima */
Ponto ou seta?

Regra mecânica: se a variável é um ponteiro, use ->; se não é, use . Em listas ligadas você praticamente só usa ->, porque quase tudo é ponteiro.

typedef: encurtando o nome

typedef struct {
    int ra;
    float nota;
} Aluno;

Aluno a;   /* em vez de: struct aluno a; */

1.4 Alocação dinâmica: criando memória durante a execução

Um vetor int v[100] tem tamanho decidido na hora de escrever o programa. Já malloc pede memória enquanto o programa roda, e devolve o endereço do pedaço reservado.

/* #include <stdlib.h> é obrigatório */

No *novo = (No*) malloc(sizeof(No));
if (novo == NULL) {
    /* memória acabou: trate o erro, não siga em frente */
}
...
free(novo);   /* devolve a memória ao sistema */

Linha por linha:

  • sizeof(No) — quantos bytes um nó ocupa. Nunca chute um número; deixe o compilador calcular.
  • malloc(...) — reserva esse tanto de bytes e devolve o endereço inicial (ou NULL se não conseguiu).
  • (No*) — converte o endereço genérico devolvido por malloc para "endereço de um No". Em C puro é opcional, mas deixa a intenção clara.
  • free(novo) — libera. Sem isso, a memória fica presa até o programa acabar (memory leak).
Três regras de free

1. Só se dá free em ponteiro que veio de malloc.
2. Depois do free, o ponteiro vira lixo — não leia mais nada dele.
3. Se você vai precisar do prox de um nó, guarde antes de liberar. Liberar e depois ler p->prox é o clássico erro de "libera lista inteira".

1.5 Tipo Abstrato de Dados (TAD)

Um TAD é a descrição de uma estrutura pelo que ela faz, não por como é feita por dentro. "Pilha" como TAD é: um conjunto de elementos com as operações criar, empilhar, desempilhar, consultar topo e testar se está vazia — e a garantia de que sai sempre o último que entrou.

Como isso é implementado por dentro (vetor? lista ligada?) é problema de quem escreve a estrutura, não de quem usa. É exatamente por isso que o título da aula é "Pilhas usando vetores e listas ligadas": mesmo TAD, duas implementações, e o código do usuário não muda.

   quem USA a pilha:   push(&p, 10);  pop(&p, &x);   <- não muda nunca
   ---------------------------------------------------
   quem IMPLEMENTA:    vetor + topo   OU   nós ligados  <- pode trocar

Na prática em C isso vira: o .h declara o tipo e as funções (a interface), o .c guarda a struct e o corpo das funções (a implementação).

Resumo do capítulo 1

  • &x pega endereço; *p acessa o conteúdo; p->campo é (*p).campo.
  • Ponteiro é variável que guarda endereço — desenhe sempre como uma seta.
  • NULL = fim de lista, estrutura vazia ou falha. Nunca desreferencie NULL.
  • malloc(sizeof(T)) cria; free(p) destrói; teste sempre o retorno de malloc.
  • TAD separa o que faz do como faz — a mesma pilha com duas implementações.

2. Pilhas

2.1 A ideia intuitiva

Uma pilha de pratos na cozinha: você coloca um prato novo em cima e, quando precisa de um, pega o de cima. Para chegar no prato do fundo, você teria que tirar todos os de cima antes. Nenhuma outra posição é acessível.

Formalmente: uma pilha é uma coleção em que inserção e remoção acontecem sempre na mesma extremidade, chamada topo. Por isso a política dela é LIFO — Last In, First Out, o último que entra é o primeiro que sai.

   push(10)   push(20)   push(30)    pop() -> 30   pop() -> 20

                          [30] topo
              [20] topo   [20]         [20] topo
   [10] topo  [10]        [10]         [10]         [10] topo
   ---------  ---------   ---------    ---------    ---------

2.2 Para que serve

Pilha é a estrutura certa sempre que o problema tem a forma "o último pendente é o próximo a resolver":

  • Ctrl+Z — desfazer sempre a última ação.
  • Botão voltar do navegador — volta para a última página visitada.
  • Chamadas de função — a famosa pilha de execução: a função que retorna é sempre a última chamada. Recursão é literalmente uma pilha.
  • Verificação de parênteses/chaves — cada fechamento casa com a última abertura em aberto.
  • Expressões pós-fixas (notação polonesa reversa) e conversão infixa→pós-fixa.

2.4 Implementação com vetor

Representação

#define MAX 100

typedef struct {
    int dados[MAX];   /* os elementos, do fundo (0) para o topo */
    int topo;         /* índice do elemento do topo; -1 = vazia  */
} Pilha;

O que cada parte significa:

  • dados[MAX] — memória já reservada, tamanho fixo. O elemento do fundo fica em dados[0].
  • topo — a única coisa que realmente "se move". Ele é o índice do último elemento inserido.
  • Por que topo começa em -1? Porque -1 não é um índice válido, então ele significa naturalmente "não tem elemento nenhum". E aí topo também vira a quantidade menos 1: com 3 elementos, topo == 2.
   Pilha com 10, 20, 30 (30 no topo):

   índice:    0     1     2     3    ...   99
            +-----+-----+-----+-----+     +-----+
   dados:   | 10  | 20  | 30  |  ?  | ... |  ?  |
            +-----+-----+-----+-----+     +-----+
                           ^
                        topo = 2

Código completo e comentado

void inicializa(Pilha *p) {
    p->topo = -1;
}

int vazia(Pilha *p) {
    return p->topo == -1;
}

int cheia(Pilha *p) {
    return p->topo == MAX - 1;
}

int push(Pilha *p, int v) {
    if (cheia(p)) return 0;      /* 0 = não deu certo (overflow) */
    p->topo++;                     /* 1) abre espaço: sobe o topo  */
    p->dados[p->topo] = v;         /* 2) escreve na nova posição   */
    return 1;
}

int pop(Pilha *p, int *saida) {
    if (vazia(p)) return 0;      /* underflow */
    *saida = p->dados[p->topo];    /* 1) copia o valor para quem chamou */
    p->topo--;                     /* 2) desce o topo                   */
    return 1;
}

int top(Pilha *p, int *saida) {
    if (vazia(p)) return 0;
    *saida = p->dados[p->topo];    /* só lê; topo não muda */
    return 1;
}

Três detalhes que valem nota:

  1. Por que Pilha *p e não Pilha p? Em C, parâmetro é cópia. Se a função recebesse uma cópia da pilha, o topo alterado morreria no fim da função. Passando o endereço, a função mexe na pilha original. Por isso quem chama escreve push(&p, 10).
  2. Por que pop devolve o valor por parâmetro? Porque o return já está sendo usado para dizer se a operação deu certo. pop(&p, &x) devolve 1/0 e coloca o valor removido em x. É a forma mais segura: um pop que retorna int direto não tem como sinalizar pilha vazia.
  3. Ordem das linhas em pop vs push: no push, primeiro sobe o índice e depois escreve; no pop, primeiro lê e depois desce. Inverter a ordem no pop faz você devolver lixo.
Elementos "removidos" continuam lá

Quando topo desce, o valor antigo não é apagado do vetor — ele só passa a estar fora da região válida. Se um exercício perguntar o conteúdo de dados[2] depois de um pop, o valor continua lá; o que mudou foi o topo. Isso é pegadinha frequente.

2.5 Implementação com lista ligada

Aqui não existe vetor: cada elemento vira um nó alocado dinamicamente, e o topo é um ponteiro para o primeiro nó da corrente.

typedef struct No {
    int info;
    struct No *prox;      /* aponta para o nó de baixo */
} No;

typedef struct {
    No *topo;             /* NULL quando a pilha está vazia */
} Pilha;
Por que struct No *prox e não No *prox?

Dentro da própria declaração, o apelido No criado pelo typedef ainda não existe. Por isso o nome struct No depois da palavra struct é obrigatório: é ele que permite o campo apontar para o próprio tipo.

   topo
    |
    v
  +----+----+    +----+----+    +----+----+
  | 30 |  *-+--->| 20 |  *-+--->| 10 |NULL|
  +----+----+    +----+----+    +----+----+
   (topo)                        (fundo)

push com lista ligada — três linhas que você precisa saber de cor

int push(Pilha *p, int v) {
    No *novo = (No*) malloc(sizeof(No));
    if (novo == NULL) return 0;

    novo->info = v;          /* 1) preenche o dado           */
    novo->prox = p->topo;    /* 2) novo aponta pro topo atual*/
    p->topo   = novo;         /* 3) topo passa a ser o novo   */
    return 1;
}

A ordem 2 → 3 é obrigatória. Veja o que acontece se você inverter:

   ORDEM CERTA                       ORDEM ERRADA (topo = novo primeiro)

   topo --> [20] --> [10]            topo --> [20] --> [10]
   novo = [30]                       novo = [30]

   (2) novo->prox = topo             (a) topo = novo
       [30] --> [20] --> [10]            topo --> [30]   ... e [20],[10]
   (3) topo = novo                       ficaram inacessíveis: VAZAMENTO
       topo --> [30] --> [20] --> [10]  (b) novo->prox = topo  ->  aponta
                                            pra ele mesmo: LOOP INFINITO
Caso da pilha vazia — funciona sozinho

Se a pilha está vazia, p->topo é NULL. Aí novo->prox = NULL, que é exatamente o que queremos para o nó do fundo. Nenhum if especial é necessário — isso é elegância de ponteiro e o professor costuma perguntar por quê.

pop com lista ligada

int pop(Pilha *p, int *saida) {
    No *aux;
    if (p->topo == NULL) return 0;

    aux    = p->topo;        /* 1) guarda quem vai sair       */
    *saida = aux->info;      /* 2) copia o valor              */
    p->topo = aux->prox;     /* 3) topo passa a ser o de baixo*/
    free(aux);               /* 4) só agora libera            */
    return 1;
}

O aux não é enfeite: sem ele, ao fazer p->topo = p->topo->prox você perde o endereço do nó antigo e não consegue mais liberá-lo. E fazer free antes de ler aux->prox é acessar memória já devolvida.

   antes:   topo --> [30] --> [20] --> [10] --> NULL
                      aux

   (3)      topo ------------> [20] --> [10] --> NULL
                      [30]  (solto, ainda alocado)

   (4)      topo ------------> [20] --> [10] --> NULL    free(aux)

Liberar a pilha inteira

void libera(Pilha *p) {
    int x;
    while (!vazia(p)) pop(p, &x);
}

2.6 Exemplos práticos, do mais simples ao mais difícil

Exemplo 1 — empilhar e esvaziar (o "olá mundo" da pilha)

Problema: ler 3 números, empilhar e imprimir na ordem inversa.

Lógica: como a pilha é LIFO, basta empilhar tudo e desempilhar até esvaziar — a inversão sai de graça.

int main(void) {
    Pilha p;
    int i, v, x;
    inicializa(&p);

    for (i = 0; i < 3; i++) {
        scanf("%d", &v);
        push(&p, v);
    }
    while (pop(&p, &x))
        printf("%d ", x);
    return 0;
}

Estado passo a passo (entrada 10, 20, 30):

   push(10):  topo=0   dados: [10]
   push(20):  topo=1   dados: [10][20]
   push(30):  topo=2   dados: [10][20][30]
   pop -> 30  topo=1
   pop -> 20  topo=0
   pop -> 10  topo=-1
   pop -> retorna 0, while termina.   Saída: 30 20 10

Repare que while (pop(&p, &x)) usa o retorno como condição: enquanto der certo, continua; quando a pilha esvazia, pop devolve 0 e o laço acaba. Esse é o padrão idiomático.

Exemplo 2 — converter decimal para binário

Problema: imprimir um número em base 2.

Lógica: divisões sucessivas por 2 geram os dígitos do menos significativo para o mais significativo — ordem invertida da que queremos imprimir. Inverter ordem é o trabalho natural de uma pilha.

void binario(int n) {
    Pilha p;
    int x;
    inicializa(&p);

    if (n == 0) { printf("0"); return; }
    while (n > 0) {
        push(&p, n % 2);   /* guarda o resto */
        n = n / 2;
    }
    while (pop(&p, &x))
        printf("%d", x);
}

   n = 13:
     13 % 2 = 1   push(1)    n=6     pilha: [1]
      6 % 2 = 0   push(0)    n=3     pilha: [1][0]
      3 % 2 = 1   push(1)    n=1     pilha: [1][0][1]
      1 % 2 = 1   push(1)    n=0     pilha: [1][0][1][1]
   desempilha: 1 1 0 1   ->   13 = 1101 (b)

Exemplo 3 — parênteses balanceados

Problema: dada uma string, dizer se os parênteses fecham corretamente. "(()())" é válido; "(()" e "())(" não.

Lógica: cada ) tem que casar com o ( mais recente ainda em aberto — é a definição de LIFO. Então: abriu, empilha; fechou, desempilha. Dois jeitos de falhar:

  • veio um ) com a pilha vazia → fechou algo que nunca abriu;
  • acabou a string com a pilha não vazia → sobrou coisa aberta.
int balanceado(const char *s) {
    Pilha p;
    int i, x;
    inicializa(&p);

    for (i = 0; s[i] != '\0'; i++) {
        if (s[i] == '(')
            push(&p, s[i]);
        else if (s[i] == ')') {
            if (!pop(&p, &x)) return 0;   /* fechou sem ter aberto */
        }
    }
    return vazia(&p);   /* sobrou aberto? então não está balanceado */
}

   s = "(()"                      s = "()()"
   '(' push   pilha: [(]          '(' push   [(]
   '(' push   pilha: [(][(]       ')' pop    []
   ')' pop    pilha: [(]          '(' push   [(]
   fim: pilha NÃO vazia -> 0      ')' pop    []
                                  fim: vazia -> 1
Versão estendida

Com (), [] e {} juntos, empilhe o próprio caractere de abertura e, ao fechar, verifique se o desempilhado é o par correspondente. Se não for, já retorna 0. Esse é um exercício clássico de prova.

2.8 Exercícios de pilha

🟢 Fácil — P1. Uma pilha vazia recebe: push(4), push(7), top(), push(1), pop(), pop(), push(9). Qual o conteúdo final da pilha (do fundo para o topo) e qual o valor devolvido por cada pop? Se fosse implementação por vetor, quanto vale topo no fim?

tente antes de abrir
Resolução comentada
   push(4)   [4]                  topo=0
   push(7)   [4][7]               topo=1
   top()     [4][7]  devolve 7    topo=1   (NÃO muda nada)
   push(1)   [4][7][1]            topo=2
   pop()     [4][7]  devolve 1    topo=1
   pop()     [4]     devolve 7    topo=0
   push(9)   [4][9]               topo=1

Pilha final, do fundo para o topo: 4, 9. Pops devolveram 1 e depois 7. topo = 1.

O ponto do exercício é o top() no meio: quem confunde top com pop erra tudo daí em diante.

🟢 Fácil — P2. Por que na pilha com vetor inicializamos topo = -1 e não topo = 0? Existe implementação correta com topo = 0? O que mudaria no push, no pop e no teste de vazia?

tente antes de abrir
Resolução comentada

Com topo = -1, o campo guarda o índice do elemento do topo. Como 0 é índice válido, precisamos de um valor fora da faixa para representar "vazia": -1.

Sim, existe a versão alternativa em que topo guarda a quantidade de elementos (ou seja, a próxima posição livre). Aí:

   topo = índice do topo        topo = quantidade / próxima livre
   -------------------------    ---------------------------------
   inicializa: topo = -1        inicializa: topo = 0
   vazia:      topo == -1       vazia:      topo == 0
   cheia:      topo == MAX-1    cheia:      topo == MAX
   push: topo++; d[topo]=v      push: d[topo]=v; topo++
   pop:  x=d[topo]; topo--      pop:  topo--; x=d[topo]
   top:  x = d[topo]            top:  x = d[topo-1]

As duas estão corretas — o que não pode é misturar as duas convenções no mesmo código. Repare que a ordem das operações em push/pop se inverte entre as versões.

Resolução comentada

Versão 1 — acesso direto ao vetor. Como estamos "dentro" da implementação, podemos varrer o vetor de trás para frente:

void imprime(Pilha *p) {
    int i;
    for (i = p->topo; i >= 0; i--)
        printf("%d ", p->dados[i]);
}

Começa em topo (o topo) e desce até 0 (o fundo). Recebe ponteiro por eficiência, mas nada é alterado.

Versão 2 — só com o TAD. Aqui não podemos olhar o vetor. A saída é desempilhar tudo em uma pilha auxiliar e depois devolver:

void imprime_tad(Pilha *p) {
    Pilha aux;
    int x;
    inicializa(&aux);

    while (pop(p, &x)) {       /* esvazia p, imprimindo do topo pro fundo */
        printf("%d ", x);
        push(&aux, x);         /* guarda na auxiliar (ordem invertida)    */
    }
    while (pop(&aux, &x))      /* devolve: inverte de novo = ordem original */
        push(p, x);
}

Por que funciona: passar de uma pilha para outra inverte a ordem. Fazendo isso duas vezes, a ordem original volta. Custo: Θ(n) de tempo e Θ(n) de espaço extra.

Isso é Θ(n), porque todo nó é visitado. Para virar Θ(1), basta guardar um contador na struct:

typedef struct { No *topo; int n; } Pilha;

E então push faz p->n++, pop faz p->n--, e tamanho só devolve p->n. Trocamos um pouco de espaço (um int) e uma linha a mais por operação por uma consulta instantânea — é o tipo de troca que o professor gosta de ver justificada.

Ideia: percorra a expressão. Se o token é número, empilhe. Se é operador, desempilhe dois, aplique e empilhe o resultado. No fim, sobra um único valor na pilha: a resposta.

int avalia(const char *s) {
    Pilha p;
    int i, a, b;
    inicializa(&p);

    for (i = 0; s[i] != '\0'; i++) {
        if (s[i] == ' ') continue;

        if (s[i] >= '0' && s[i] <= '9') {
            push(&p, s[i] - '0');        /* char -> int */
        } else {
            pop(&p, &b);                 /* PRIMEIRO a sair é o da DIREITA */
            pop(&p, &a);                 /* o segundo é o da ESQUERDA      */
            switch (s[i]) {
                case '+': push(&p, a + b); break;
                case '-': push(&p, a - b); break;
                case '*': push(&p, a * b); break;
                case '/': push(&p, a / b); break;
            }
        }
    }
    pop(&p, &a);
    return a;
}

Por que a ordem importa: na expressão "7 3 -", o 7 entrou primeiro e o 3 depois. Como a pilha é LIFO, o primeiro pop devolve 3 (o operando da direita) e o segundo devolve 7 (o da esquerda). Se você fizesse push(&p, b - a), obteria -4 em vez de 4. Em + e * o erro passa despercebido porque são comutativos — e é justamente por isso que a prova usa - ou /.

   "3 4 + 2 *"
   '3' push       [3]
   '4' push       [3][4]
   '+' pop b=4, pop a=3, push 3+4   [7]
   '2' push       [7][2]
   '*' pop b=2, pop a=7, push 7*2   [14]
   resultado: 14

Resumo do capítulo 2

  • Pilha = LIFO. Insere e remove só no topo.
  • Vetor: topo é índice, começa em -1; push sobe e escreve, pop lê e desce.
  • Lista ligada: topo é ponteiro, começa NULL; push é novo->prox = topo; topo = novo; nessa ordem.
  • pop guarda o nó em aux, move o topo, e só então dá free.
  • Todas as operações principais são Θ(1) nas duas versões.
  • Usos típicos: inverter ordem, desfazer, casar aberturas/fechamentos, avaliar pós-fixa, recursão.

3. Filas

3.1 A ideia intuitiva

A fila do banco: quem chega entra no fim, quem é atendido sai do começo. Ninguém fura. Formalmente, uma fila é uma coleção em que a inserção acontece em uma extremidade (o fim) e a remoção na outra (o início). A política é FIFO — First In, First Out.

   sai daqui                              entra aqui
   (início / frente)                      (fim / trás)
      |                                       |
      v                                       v
    [ 10 ][ 20 ][ 30 ][ 40 ]  <---- enqueue(50)
      ^
   dequeue() devolve 10
Vocabulário

O mesmo conceito aparece com nomes diferentes nos livros: início = frente = inicio = front = head; fim = trás = fim = rear = tail. Inserir é enqueue (ou enfileirar); remover é dequeue (ou desenfileirar).

3.2 A diferença entre início e fim (o ponto que confunde)

Na pilha existe um ponto de acesso; na fila existem dois, e cada um serve para uma coisa só:

Início (frente)Fim (trás)
O que éo elemento mais antigoo elemento mais recente
Quem mexedequeue (sai)enqueue (entra)
Consultafrente() — o próximo a ser atendidofim() — o último que chegou

Confundir os dois é o erro número 1 de fila: se você inserir no início e remover do início, acabou de escrever uma pilha.

3.3 Para que serve

  • Fila de impressão — o primeiro documento enviado imprime primeiro.
  • Escalonamento de processos no sistema operacional; atendimento em call center.
  • Buffer de dados: quem produz e quem consome em ritmos diferentes.
  • Busca em largura (BFS) em grafos e árvores — o percurso por nível usa fila. Isso volta na aula de grafos e no percurso em árvore.

3.4 Implementação com vetor — e o problema do "andar para a direita"

A tentativa ingênua: um vetor com dois índices, inicio e fim. Insere no fim e incrementa fim; remove do início e incrementa inicio. Funciona... por um tempo:

   MAX = 5

   após 5 enqueues e 3 dequeues:

   índice:   0     1     2     3     4
           +-----+-----+-----+-----+-----+
           |  x  |  x  |  30 |  40 |  50 |
           +-----+-----+-----+-----+-----+
                          ^                 ^
                       inicio=2           fim=5

   Só há 3 elementos, mas fim chegou ao limite:
   um novo enqueue seria recusado, com 2 posições livres no começo!

A fila "anda" pelo vetor e desperdiça as posições já usadas. Duas soluções:

  1. Deslocar tudo a cada remoção — mantém inicio = 0 sempre, mas cada dequeue custa Θ(n). Ruim.
  2. Fila circular — quando um índice passa do fim do vetor, ele volta para a posição 0. Custo Θ(1). É a solução padrão.

A ideia da fila circular

Imagine o vetor dobrado em um anel: depois da posição MAX-1 vem a posição 0. O operador que faz essa mágica é o resto da divisão:

   proximo = (atual + 1) % MAX

   MAX = 5:  (0+1)%5=1   (3+1)%5=4   (4+1)%5=0   <- deu a volta

                   [0]
              [4]       [1]
                   ...
              [3]       [2]

Representação: início + quantidade

Existe uma armadilha clássica em fila circular: guardando inicio e fim, a condição "fila cheia" e "fila vazia" ficam idênticas (inicio == fim) e você não consegue distinguir. A saída mais limpa é guardar início e quantidade:

#define MAX 100

typedef struct {
    int dados[MAX];
    int inicio;   /* índice do primeiro elemento */
    int qtd;      /* quantos elementos existem    */
} Fila;

Com isso, o índice do fim é calculado quando precisa: (inicio + qtd) % MAX é a primeira posição livre.

void inicializa(Fila *f) {
    f->inicio = 0;
    f->qtd    = 0;
}

int vazia(Fila *f) { return f->qtd == 0; }
int cheia(Fila *f) { return f->qtd == MAX; }

int enqueue(Fila *f, int v) {
    int fim;
    if (cheia(f)) return 0;
    fim = (f->inicio + f->qtd) % MAX;   /* 1ª posição livre     */
    f->dados[fim] = v;                  /* escreve no fim       */
    f->qtd++;                           /* a fila cresceu       */
    return 1;
}

int dequeue(Fila *f, int *saida) {
    if (vazia(f)) return 0;
    *saida = f->dados[f->inicio];            /* 1) lê o mais antigo  */
    f->inicio = (f->inicio + 1) % MAX;      /* 2) avança circular   */
    f->qtd--;                                /* 3) a fila encolheu   */
    return 1;
}

int frente(Fila *f, int *saida) {
    if (vazia(f)) return 0;
    *saida = f->dados[f->inicio];   /* só lê */
    return 1;
}

Por que isso resolve tudo: qtd == 0 é vazia e qtd == MAX é cheia, sem ambiguidade nenhuma. E o % MAX aparece em exatamente dois lugares — no cálculo do fim e no avanço do início.

Se o professor usou inicio e fim

Também é comum a versão com dois índices sacrificando uma posição do vetor: a fila é considerada cheia quando (fim + 1) % MAX == inicio, o que deixa sempre uma casa vazia para diferenciar de inicio == fim (vazia). É correta, só cabe MAX-1 elementos. Saiba reconhecer as duas.

Rastreando uma fila circular pequena

   MAX = 4, fila vazia: inicio=0, qtd=0

   enqueue(10)  fim=(0+0)%4=0  d[0]=10   inicio=0 qtd=1   [10][ ][ ][ ]
   enqueue(20)  fim=(0+1)%4=1  d[1]=20   inicio=0 qtd=2   [10][20][ ][ ]
   enqueue(30)  fim=(0+2)%4=2  d[2]=30   inicio=0 qtd=3   [10][20][30][ ]
   dequeue -> 10                         inicio=1 qtd=2   [__][20][30][ ]
   enqueue(40)  fim=(1+2)%4=3  d[3]=40   inicio=1 qtd=3   [__][20][30][40]
   enqueue(50)  fim=(1+3)%4=0  d[0]=50   inicio=1 qtd=4   [50][20][30][40]
                                          ^ deu a volta e ocupou a casa livre
   enqueue(60)  qtd==MAX -> recusa (retorna 0)
   dequeue -> 20                         inicio=2 qtd=3

3.5 Implementação com lista ligada

Sem limite de tamanho e sem aritmética circular. A diferença em relação à pilha: precisamos guardar dois ponteiros, porque mexemos nas duas pontas.

typedef struct No {
    int info;
    struct No *prox;
} No;

typedef struct {
    No *inicio;   /* de onde sai (dequeue) */
    No *fim;      /* onde entra (enqueue)  */
} Fila;

   inicio                                     fim
     |                                         |
     v                                         v
   +----+----+   +----+----+   +----+----+
   | 10 |  *-+-->| 20 |  *-+-->| 30 |NULL|
   +----+----+   +----+----+   +----+----+

   Atenção ao sentido das setas: elas apontam do início para o fim.
   Por isso dá para remover do início em Θ(1) (basta andar uma casa)
   e inserir no fim em Θ(1) (porque guardamos o ponteiro 'fim').

enqueue: inserir no fim

int enqueue(Fila *f, int v) {
    No *novo = (No*) malloc(sizeof(No));
    if (novo == NULL) return 0;

    novo->info = v;
    novo->prox = NULL;              /* ele será o último */

    if (f->inicio == NULL)          /* fila estava vazia:            */
        f->inicio = novo;           /* o novo é início E fim         */
    else
        f->fim->prox = novo;        /* engata depois do último atual  */

    f->fim = novo;                  /* nos dois casos, fim = novo     */
    return 1;
}

O if aqui é necessário (diferente do push da pilha, que não precisava de caso especial). Motivo: se a fila está vazia, f->fim é NULL, e f->fim->prox = novo seria desreferenciar NULL — segmentation fault na hora.

   Fila vazia:                Fila com elementos:
   inicio=NULL  fim=NULL      inicio -> [10] -> [20] <- fim

   novo=[30]                  novo=[30]
   inicio = novo              fim->prox = novo:
   fim    = novo                inicio -> [10] -> [20] -> [30]
   inicio -> [30] <- fim      fim = novo:
                                inicio -> [10] -> [20] -> [30] <- fim

dequeue: remover do início

int dequeue(Fila *f, int *saida) {
    No *aux;
    if (f->inicio == NULL) return 0;

    aux       = f->inicio;       /* 1) guarda quem sai         */
    *saida    = aux->info;       /* 2) copia o valor           */
    f->inicio = aux->prox;       /* 3) início anda uma casa    */

    if (f->inicio == NULL)       /* 4) saiu o último elemento? */
        f->fim = NULL;           /*    então fim também zera   */

    free(aux);                   /* 5) libera                  */
    return 1;
}
O passo 4 é a pegadinha favorita da fila encadeada

Se você esquecer de zerar f->fim ao remover o último elemento, ele continua apontando para um nó que acabou de ser liberado. No próximo enqueue, a fila parece vazia (inicio == NULL), então o código vai pelo ramo do if... mas em outra implementação que teste vazia por fim, ou que use fim->prox, você escreve em memória liberada. É um bug silencioso — o programa pode até "funcionar" e quebrar depois.

3.6 Exemplos práticos

Exemplo 1 — atendimento simples

Problema: três clientes chegam (senhas 101, 102, 103) e dois são atendidos. Quem está na frente depois?

int main(void) {
    Fila f;
    int x;
    inicializa(&f);

    enqueue(&f, 101);
    enqueue(&f, 102);
    enqueue(&f, 103);

    dequeue(&f, &x);  printf("atendido: %d\n", x);
    dequeue(&f, &x);  printf("atendido: %d\n", x);
    frente(&f, &x);   printf("na frente: %d\n", x);
    return 0;
}

   enqueue(101)   inicio -> [101] <- fim
   enqueue(102)   inicio -> [101] -> [102] <- fim
   enqueue(103)   inicio -> [101] -> [102] -> [103] <- fim
   dequeue -> 101 inicio -> [102] -> [103] <- fim
   dequeue -> 102 inicio -> [103] <- fim
   frente  -> 103 (nada muda)

   Saída: atendido 101 / atendido 102 / na frente 103

Exemplo 2 — imprimir e devolver (percorrer sem destruir)

Problema: imprimir a fila do início ao fim usando só o TAD, deixando-a como estava.

Lógica: ao contrário da pilha, a fila preserva a ordem quando você passa todos os elementos por ela. Então basta remover da frente e reinserir no fim, exatamente n vezes.

void imprime(Fila *f, int n) {   /* n = quantidade de elementos */
    int i, x;
    for (i = 0; i < n; i++) {
        dequeue(f, &x);
        printf("%d ", x);
        enqueue(f, x);      /* volta para o fim */
    }
}

   [10][20][30]  -> deq 10, imprime, enq 10  -> [20][30][10]
                 -> deq 20, imprime, enq 20  -> [30][10][20]
                 -> deq 30, imprime, enq 30  -> [10][20][30]  (voltou!)

Depois de n rodadas, a fila está idêntica. Com a pilha, o mesmo truque precisava de estrutura auxiliar; com a fila, a rotação resolve. Cuidado: o laço precisa ser limitado por n, senão ele gira para sempre.

Exemplo 3 — o problema de Josephus (eliminação circular)

Problema: n pessoas em círculo, numeradas 1..n. Conta-se de k em k e quem cai na contagem sai. Quem sobra?

Lógica: "voltar para o fim da fila" é o mesmo que "continuar no círculo". Então: k-1 pessoas são rodadas (sai da frente, volta pro fim) e a k-ésima é removida de vez. Repete até sobrar uma.

int josephus(int n, int k) {
    Fila f;
    int i, x;
    inicializa(&f);

    for (i = 1; i <= n; i++) enqueue(&f, i);

    while (n > 1) {
        for (i = 0; i < k - 1; i++) {   /* k-1 sobreviventes rodam */
            dequeue(&f, &x);
            enqueue(&f, x);
        }
        dequeue(&f, &x);                 /* o k-ésimo é eliminado   */
        n--;
    }
    dequeue(&f, &x);
    return x;
}

   n=5, k=2:
   [1][2][3][4][5]  roda 1: [2][3][4][5][1]  elimina 2 -> [3][4][5][1]
                    roda 3: [4][5][1][3]     elimina 4 -> [5][1][3]
                    roda 5: [1][3][5]        elimina 1 -> [3][5]
                    roda 3: [5][3]           elimina 5 -> [3]
   sobrevivente: 3

🟢 Fácil — F2. Por que uma fila encadeada precisa de dois ponteiros (inicio e fim) enquanto a pilha encadeada precisa de apenas um? E se as setas dos nós apontassem do fim para o início, o que mudaria?

tente antes de abrir
Resolução comentada

A pilha mexe em uma extremidade só, então um ponteiro (topo) basta. A fila mexe nas duas: remove no início e insere no fim. Você até poderia guardar só o inicio, mas cada enqueue teria que percorrer a lista até o último nó — Θ(n) em vez de Θ(1). O ponteiro fim é um atalho que compra tempo constante.

Se as setas apontassem do fim para o início, o enqueue (inserir no fim) continuaria fácil, mas o dequeue ficaria caro: para remover o nó do início, seria preciso achar quem aponta para ele — e, com setas nesse sentido, isso exige varrer tudo, Θ(n). Por isso o encadeamento correto é sempre início → fim.

🟡 Médio — F3. Implemente int fim_valor(Fila *f, int *saida) nas duas versões (vetor circular e lista ligada): devolve o último elemento inserido sem removê-lo.

Vetor circular. A primeira posição livre é (inicio + qtd) % MAX, então o último elemento está uma posição antes dela:

int fim_valor(Fila *f, int *saida) {

Por que não idx - 1 direto? Porque se a primeira livre é 0, o último está em MAX-1, e só o % faz essa volta. Como testamos vazia antes, qtd >= 1 e a conta nunca fica negativa.

int fim_valor(Fila *f, int *saida) {

void inverte_fila(Fila *f) {

🔴 Difícil — F5. Implemente uma pilha usando duas filas: as funções push, pop e vazia devem respeitar LIFO, mas por dentro você só pode usar enqueue, dequeue e vazia de filas. Qual o custo de cada operação?

tente antes de abrir
Resolução comentada

Ideia: a fila entrega o mais antigo, mas queremos o mais recente. A saída é fazer o elemento recém-inserido "ir para a frente". Estratégia com push caro:

  1. Insere o novo elemento na fila auxiliar f2 (que está vazia).
  2. Transfere todo mundo de f1 para f2, na ordem.
  3. Troca os papéis de f1 e f2.

O resultado é que f1 sempre tem o elemento mais recente na frente, e o pop vira um simples dequeue.

typedef struct { Fila f1, f2; } PilhaDeFilas;

void push(PilhaDeFilas *p, int v) {
    int x;
    enqueue(&p->f2, v);                  /* o novo entra sozinho na f2 */
    while (dequeue(&p->f1, &x))          /* todos os antigos vão atrás */
        enqueue(&p->f2, x);
    troca(&p->f1, &p->f2);               /* f2 vira a principal        */
}

int pop(PilhaDeFilas *p, int *saida) {
    return dequeue(&p->f1, saida);
}

int vazia(PilhaDeFilas *p) {
    return fila_vazia(&p->f1);
}
   push(10): f2=[10]                  troca -> f1=[10]
   push(20): f2=[20], move 10         f2=[20][10]  troca -> f1=[20][10]
   push(30): f2=[30], move 20,10      f2=[30][20][10]      f1=[30][20][10]
   pop -> dequeue -> 30   (LIFO, correto!)

Custos: push é Θ(n), porque move todos os elementos; pop e vazia são Θ(1). Existe a estratégia simétrica (push Θ(1) e pop Θ(n), transferindo n-1 elementos na remoção). O ponto do exercício é perceber que, para transformar FIFO em LIFO, alguém tem que pagar Θ(n) em algum lugar.

Resumo do capítulo 3

  • Fila = FIFO. Entra no fim (enqueue), sai do início (dequeue).
  • Com vetor, use a forma circular: (indice + 1) % MAX; guardar inicio + qtd elimina a ambiguidade entre vazia e cheia.
  • Com lista ligada, dois ponteiros: inicio e fim. As setas vão do início para o fim.
  • enqueue precisa do if de fila vazia; dequeue precisa zerar fim quando sai o último.
  • Todas as operações são Θ(1) nas duas implementações bem-feitas.
  • Pilha inverte a ordem; fila preserva. Isso decide qual usar.

4. Listas ligadas

4.1 A ideia intuitiva

Uma caça ao tesouro: você recebe um bilhete com uma informação e o endereço do próximo bilhete. Chega lá, lê a informação, pega o endereço seguinte, e assim por diante até um bilhete que diz "acabou". Os bilhetes podem estar espalhados pela cidade inteira — o que os mantém em ordem não é a posição, é o endereço que cada um carrega.

Uma lista ligada (ou encadeada) é isso: uma sequência de nós, cada um com um dado e o endereço do próximo. O último aponta para NULL, que é o "acabou".

   lista
     |
     v
   +----+----+   +----+----+   +----+----+
   | 10 |  *-+-->| 20 |  *-+-->| 30 |NULL|
   +----+----+   +----+----+   +----+----+
    info prox

   Forma compacta que usaremos daqui pra frente:
   [10] -> [20] -> [30] -> NULL

4.2 Que problema ela resolve

O vetor tem dois defeitos difíceis de contornar:

  1. Tamanho fixo. Você precisa decidir MAX antes de rodar. Chuta alto e desperdiça memória; chuta baixo e estoura.
  2. Inserção e remoção no meio custam caro. Para inserir na posição 0 de um vetor com n elementos, é preciso empurrar todos os n uma casa para a direita: Θ(n).
   VETOR: inserir 5 no início              LISTA: inserir 5 no início
   [10][20][30][ ]                         [10]->[20]->[30]->NULL
       desloca tudo ->                     cria [5], aponta para [10],
   [ ][10][20][30]                         muda a cabeça:
   [5][10][20][30]     Θ(n)                [5]->[10]->[20]->[30]  Θ(1)

A lista ligada cresce sob demanda (um malloc por nó) e insere/remove em tempo constante desde que você já esteja com o ponteiro na posição certa. Em troca, ela perde o acesso direto: não existe lista[7], só dá para chegar no sétimo nó andando do primeiro até ele.

4.3 O nó e a cabeça da lista

typedef struct No {
    int info;              /* o dado guardado           */
    struct No *prox;       /* endereço do próximo nó     */
} No;                      /* prox = NULL no último nó  */

A lista inteira é representada por um ponteiro para o primeiro nó — a cabeça. Uma lista vazia é simplesmente a cabeça valendo NULL:

No *lista = NULL;      /* lista vazia */

int vazia(No *l) {
    return l == NULL;
}
Duas convenções para as funções que alteram a lista

(a) Retornando a nova cabeça: No* insere_inicio(No *l, int v), usada como lista = insere_inicio(lista, 5);. É a mais comum em livros de C e a que usaremos aqui.

(b) Recebendo ponteiro para ponteiro: void insere_inicio(No **l, int v), usada como insere_inicio(&lista, 5);. Necessária quando a função precisa mudar a cabeça sem retorná-la.

As duas existem pelo mesmo motivo: quem insere no início ou remove o primeiro nó muda o valor da cabeça, e uma função C não consegue alterar o argumento do chamador sem uma dessas duas saídas. Saiba explicar isso — é pergunta de prova.

4.4 Percurso: a operação-mãe

Quase toda função de lista é uma variação deste laço. Aprenda-o de cor:

void imprime(No *l) {
    No *p;
    for (p = l; p != NULL; p = p->prox)
        printf("[%d] -> ", p->info);
    printf("NULL\n");
}

Linha por linha:

  • p = l — o ponteiro auxiliar começa na cabeça. Nunca caminhe usando l diretamente se você ainda precisa da lista.
  • p != NULL — condição de parada. NULL é o fim; testar isso é o que impede o acesso inválido.
  • p = p->prox — o passo. É literalmente "siga a seta".
   p            p            p            p
   |            |            |            |
   v            v            v            v
  [10]  ->     [20]  ->     [30]  ->    NULL   (o laço para aqui)
Confusão clássica: p != NULL ou p->prox != NULL?

Use p != NULL quando quiser visitar todos os nós. Use p->prox != NULL quando quiser parar no último nó (por exemplo, para inserir depois dele). No segundo caso, a lista vazia tem que ser tratada antes, senão p->prox explode com p valendo NULL.

4.5 Inserção no início — Θ(1)

No* insere_inicio(No *l, int v) {
    No *novo = (No*) malloc(sizeof(No));
    if (novo == NULL) return l;   /* sem memória: lista intacta */

    novo->info = v;
    novo->prox = l;     /* o novo aponta para a antiga cabeça */
    return novo;        /* o novo É a nova cabeça             */
}

   antes:   l -> [10] -> [20] -> NULL      novo = [5]

   (1) novo->prox = l:
            [5] -> [10] -> [20] -> NULL
             ^
            novo         l ainda aponta pro [10]

   (2) return novo  ... e o chamador faz  lista = novo:
            lista -> [5] -> [10] -> [20] -> NULL

Lista vazia funciona sem if: l é NULL, então novo->prox = NULL e a lista passa a ter um nó só. É o mesmo raciocínio do push da pilha encadeada — na verdade, uma pilha encadeada é exatamente uma lista com inserção e remoção só no início.

4.6 Inserção no final — Θ(n)

Aqui precisamos achar o último nó antes de engatar. E o último nó é aquele cujo prox é NULL.

No* insere_fim(No *l, int v) {
    No *p;
    No *novo = (No*) malloc(sizeof(No));
    if (novo == NULL) return l;

    novo->info = v;
    novo->prox = NULL;              /* ele vai ser o último */

    if (l == NULL) return novo;   /* lista vazia: novo vira a cabeça */

    p = l;
    while (p->prox != NULL)         /* anda até o ÚLTIMO nó   */
        p = p->prox;
    p->prox = novo;                 /* engata                 */
    return l;                       /* a cabeça não mudou     */
}

                    p                       p
                    |                       |
   [10] -> [20] -> [30] -> NULL            [30] -> [40] -> NULL
                    ^                              ^
        para aqui (p->prox == NULL)             p->prox = novo

Três pontos de atenção:

  • O teste l == NULL vem antes do laço. Sem ele, p->prox com p NULL é falha de segmentação.
  • A condição é p->prox != NULL, não p != NULL. Se fosse a segunda, p terminaria valendo NULL e você não teria mais como alcançar o último nó.
  • Retornamos l, não novo: inserir no fim não muda a cabeça (exceto na lista vazia).

4.7 Inserção em uma posição

Para inserir na posição pos (contando de 0), precisamos do nó da posição pos-1 — o anterior. Esse é o princípio geral: em lista simplesmente ligada, para mexer em um nó você precisa do anterior a ele.

No* insere_pos(No *l, int v, int pos) {
    No *novo, *p;
    int i;

    if (pos <= 0) return insere_inicio(l, v);   /* caso especial */

    p = l;
    for (i = 0; i < pos - 1 && p != NULL; i++)
        p = p->prox;                /* para no nó pos-1 */

    if (p == NULL) return l;       /* posição não existe */

    novo = (No*) malloc(sizeof(No));
    if (novo == NULL) return l;

    novo->info = v;
    novo->prox = p->prox;          /* 1) novo aponta pro que vinha depois */
    p->prox    = novo;              /* 2) anterior aponta pro novo         */
    return l;
}
A ordem 1 → 2 é inegociável

Se você fizer p->prox = novo primeiro, perde o endereço do resto da lista — e aí novo->prox = p->prox faz o novo nó apontar para si mesmo. Resultado: metade da lista vaza e um percurso entra em laço infinito. Sempre ligue o novo nó ao resto antes de cortar a ligação antiga.

   inserir 15 na posição 1 de [10] -> [20] -> [30] -> NULL

   p para no nó de índice 0:     p = [10]
   novo = [15]

   (1) novo->prox = p->prox
                    [15]
                       \
        [10] -------> [20] -> [30] -> NULL

   (2) p->prox = novo
        [10] -> [15] -> [20] -> [30] -> NULL

4.8 Busca

No* busca(No *l, int v) {
    No *p = l;
    while (p != NULL) {
        if (p->info == v) return p;   /* achou: devolve o nó */
        p = p->prox;
    }
    return NULL;                      /* não achou           */
}

A busca é sempre sequencial: Θ(n) no pior caso, Θ(1) no melhor (o primeiro já é). Mesmo que a lista esteja ordenada, não dá para fazer busca binária, porque não existe acesso direto ao elemento do meio — chegar nele já custaria Θ(n). Essa é uma comparação que cai em prova, e conecta com a aula 10 (busca sequencial × binária).

Em lista ordenada, dá para uma otimização: parar assim que p->info > v, já que dali para frente todos são maiores. Continua Θ(n) no pior caso, mas melhora o caso médio.

4.9 Remoção

Remover exige três coisas: achar o nó, achar o anterior dele, e tratar o caso de o nó ser o primeiro.

No* remove_valor(No *l, int v) {
    No *ant = NULL;     /* nó anterior ao p         */
    No *p   = l;        /* nó candidato à remoção   */

    while (p != NULL && p->info != v) {
        ant = p;
        p   = p->prox;
    }

    if (p == NULL) return l;    /* não achou: nada muda         */

    if (ant == NULL)              /* era o primeiro nó            */
        l = p->prox;              /*   a cabeça passa a ser o 2º  */
    else
        ant->prox = p->prox;      /*   o anterior "pula" o p      */

    free(p);
    return l;
}

Entendendo cada decisão:

  • Por que dois ponteiros? Porque em lista simplesmente ligada não existe caminho de volta. Quando você encontra o nó, só o anterior consegue reapontar para depois dele.
  • Por que ant começa em NULL? Justamente para sinalizar "ainda não passei por ninguém", ou seja, o nó encontrado é o primeiro.
  • Ordem no while: p != NULL && p->info != v. Nessa ordem, quando p é NULL o C nem avalia a segunda parte (avaliação em curto-circuito). Invertendo, você desreferencia NULL ao chegar no fim.
  • free(p) por último, depois de já ter usado p->prox.
   remover 20 de  [10] -> [20] -> [30] -> NULL

   ant = [10]   p = [20]

   ant->prox = p->prox:
        [10] ----------> [30] -> NULL
                [20] (solto)
   free(p):
        [10] -> [30] -> NULL

   ------------------------------------------------
   remover 10 (o primeiro):   ant = NULL, p = [10]

   l = p->prox:
        l -> [20] -> [30] -> NULL      free([10])

4.10 Liberar a lista inteira

void libera(No *l) {
    No *p = l;
    No *t;
    while (p != NULL) {
        t = p->prox;   /* guarda o próximo ANTES de liberar */
        free(p);
        p = t;
    }
}
Por que t é obrigatório

Este código está errado: while (p != NULL) { free(p); p = p->prox; }. Depois do free, a memória de p foi devolvida ao sistema; ler p->prox é acessar memória inválida. Pode até "parecer funcionar" no seu computador e falhar na correção — é comportamento indefinido.

Exemplo 1 — montando e imprimindo uma lista

Exemplo 2 — contar elementos e somar

int tamanho(No *l) {

É o mesmo percurso do imprime, trocando só o que se faz dentro do laço. Uma vez que o percurso está na mão, metade dos exercícios de lista viram variações de cinco linhas.

Exemplo 3 — inserir mantendo a lista ordenada

Problema: inserir um valor de modo que a lista continue em ordem crescente.

Lógica: ande enquanto os valores forem menores que v, guardando o anterior. Pare no primeiro maior ou igual — o novo nó entra ali.

No* insere_ordenado(No *l, int v) {
    No *ant = NULL, *p = l;
    No *novo;

    while (p != NULL && p->info < v) {
        ant = p;
        p   = p->prox;
    }

    novo = (No*) malloc(sizeof(No));
    if (novo == NULL) return l;
    novo->info = v;
    novo->prox = p;              /* aponta pro primeiro maior/igual */

    if (ant == NULL) return novo;   /* entrou no início: nova cabeça */
    ant->prox = novo;
    return l;
}

   inserir 25 em  [10] -> [20] -> [30] -> NULL

   p=[10] (10<25) ant=[10] -> p=[20] (20<25) ant=[20] -> p=[30] (30<25? não) para

   novo->prox = p:      [25] -> [30]
   ant->prox = novo:    [10] -> [20] -> [25] -> [30] -> NULL

Este código cobre os três casos sozinho: inserir no início (ant continua NULL), no meio, e no fim (p chega a NULL e novo->prox = NULL é exatamente o certo).

Exemplo 4 — inverter a lista (o exercício de ponteiros por excelência)

Problema: inverter a lista in loco, sem criar nós novos. Só virando as setas.

Lógica: percorra a lista mudando o prox de cada nó para apontar para o anterior. Como isso destrói o caminho para frente, é preciso guardar o próximo antes de virar a seta. Três ponteiros: ant, p, prox.

No* inverte(No *l) {
    No *ant = NULL, *p = l, *prox;

    while (p != NULL) {
        prox     = p->prox;   /* 1) salva o caminho de volta */
        p->prox  = ant;        /* 2) vira a seta              */
        ant      = p;          /* 3) anda: ant vira o atual   */
        p        = prox;       /* 4) e o atual vira o próximo */
    }
    return ant;   /* ant parou no último nó = nova cabeça */
}

   início:   ant=NULL   p=[10] -> [20] -> [30] -> NULL

   iter 1:   prox=[20]; [10]->NULL;  ant=[10];  p=[20]
             NULL <- [10]      [20] -> [30] -> NULL

   iter 2:   prox=[30]; [20]->[10];  ant=[20];  p=[30]
             NULL <- [10] <- [20]      [30] -> NULL

   iter 3:   prox=NULL; [30]->[20];  ant=[30];  p=NULL
             NULL <- [10] <- [20] <- [30]

   p == NULL -> para. return ant = [30]
   nova lista: [30] -> [20] -> [10] -> NULL

Se cair "inverta uma lista" na prova, desenhe esses três ponteiros antes de escrever qualquer linha. Sem o desenho, quase todo mundo esquece de salvar prox e perde metade da lista na primeira iteração.

4.13 Variações (fique sabendo que existem)

  • Lista com nó-cabeça (sentinela): um primeiro nó falso, sem dado, que nunca é removido. Vantagem: a cabeça nunca muda, então some o caso especial "remover o primeiro" e as funções podem ser void. Vários livros brasileiros usam essa forma.
  • Lista duplamente ligada: cada nó guarda prox e ant. Dá para andar nos dois sentidos e remover um nó tendo só o ponteiro para ele. Custa um ponteiro a mais por nó e mais ligações para atualizar.
  • Lista circular: o último aponta de volta para o primeiro em vez de NULL. Cuidado: o percurso não pode testar NULL, e sim "voltei ao ponto de partida".

Se o professor não cobriu isso em sala, não vai cair implementação — mas reconhecer a diferença é comum em questão conceitual.

🟢 Fácil — L2. Explique, sem código, por que insere_inicio é Θ(1) e insere_fim é Θ(n) numa lista simplesmente ligada — e por que num vetor é exatamente o contrário.

tente antes de abrir
Resolução comentada

Na lista: a cabeça é conhecida de imediato, então inserir no início é criar um nó e ajustar duas setas — um número fixo de passos, independente de n. Já o fim não é conhecido: só se descobre quem é o último andando nó a nó até achar prox == NULL, o que são n passos.

No vetor: o fim é conhecido de imediato (é a posição qtd), então inserir lá é uma atribuição, Θ(1). Já inserir no início obriga a empurrar os n elementos uma casa para a direita, Θ(n).

Resumo em uma frase: cada estrutura é rápida na ponta que ela consegue enxergar sem procurar. Por isso a lista com ponteiro extra para o fim recupera o Θ(1) na inserção final — é exatamente o que a fila encadeada faz.

🟡 Médio — L3. Implemente No* remove_pos(No *l, int pos), que remove o nó da posição pos (contando de 0). Trate: posição 0, posição inexistente e lista vazia.

tente antes de abrir
Resolução comentada
No* remove_pos(No *l, int pos) {
    No *ant = NULL, *p = l;
    int i;

    if (l == NULL || pos < 0) return l;       /* lista vazia ou pos inválida */

    for (i = 0; i < pos && p != NULL; i++) {  /* anda até a posição pedida   */
        ant = p;
        p   = p->prox;
    }

    if (p == NULL) return l;                  /* posição não existe          */

    if (ant == NULL) l = p->prox;             /* removendo o primeiro        */
    else ant->prox = p->prox;

Diferença em relação ao remove_valor: o critério de parada é o contador, não a comparação de conteúdo. A estrutura (dois ponteiros, caso do primeiro nó, free no fim) é idêntica — e é essa estrutura que você deve ter memorizada.

O && p != NULL dentro do for é o que protege contra pos maior que o tamanho: o laço para em NULL e o if seguinte devolve a lista intacta.

🟡 Médio — L4. Escreva No* concatena(No *a, No *b), que engata a lista b no fim da lista a e devolve a cabeça do resultado, sem criar nós novos. Trate os casos de lista vazia.

Resolução comentada
No* concatena(No *a, No *b) {
    No *p;

    if (b == NULL) return a;     /* b vazia: nada a fazer    */

🔴 Difícil — L5. Escreva No* remove_duplicados(No *l) para uma lista ordenada crescente, deixando só uma ocorrência de cada valor. Exemplo: [1]->[1]->[2]->[3]->[3]->[3] vira [1]->[2]->[3]. Qual é a complexidade?

Resolução comentada

Ideia: como a lista está ordenada, duplicatas são sempre vizinhas. Então basta comparar cada nó com o seguinte e, quando forem iguais, remover o seguinte.

No* remove_duplicados(No *l) {
    No *p = l;
    No *lixo;

    while (p != NULL && p->prox != NULL) {
        if (p->info == p->prox->info) {
            lixo    = p->prox;          /* guarda quem vai sair    */
            p->prox = lixo->prox;       /* pula por cima dele       */
            free(lixo);
            /* NÃO avança p: pode haver outra duplicata em seguida  */
        } else {
            p = p->prox;                /* só avança quando difere  */
        }
    }
    return l;
}

Os dois pontos que separam quem entendeu de quem decorou:

  1. Não avançar p após remover. Em [3]->[3]->[3], se você avançasse, sobraria uma duplicata. Ficando parado, o mesmo p compara de novo com o novo vizinho.
  2. A condição dupla no while. p->prox != NULL garante que existe um vizinho para comparar; p != NULL protege a lista vazia. A ordem importa por causa do curto-circuito.
   [1]->[1]->[2]->[3]->[3]->[3]->NULL
    p    igual -> remove o 2º [1]
   [1]->[2]->[3]->[3]->[3]->NULL
    p    difere -> avança
   [1]->[2]->[3]->[3]->[3]  p=[2] difere -> avança
                  p=[3] igual -> remove   [1]->[2]->[3]->[3]
                  p=[3] igual -> remove   [1]->[2]->[3]
                  p->prox == NULL -> para

Complexidade: Θ(n). Cada nó é visitado no máximo uma vez para comparar e no máximo uma vez para ser removido; nenhum passo repete o percurso.

E se a lista não fosse ordenada? Aí as duplicatas podem estar longe uma da outra e a solução direta é, para cada nó, varrer o resto da lista removendo iguais — Θ(n²). Saber apontar essa diferença rende ponto.

Resumo do capítulo 4

  • Nó = dado + ponteiro para o próximo; a lista é o ponteiro para o primeiro nó; NULL marca o fim e a lista vazia.
  • Percurso padrão: for (p = l; p != NULL; p = p->prox). Nunca caminhe com a cabeça.
  • Inserir no início: novo->prox = l; return novo; — Θ(1).
  • Inserir no fim ou no meio: ache o anterior; ligue o novo ao resto antes de religar o anterior.
  • Remover: precisa de ant e p; trate o primeiro nó (ant == NULL); free só depois de usar p->prox.
  • Busca sequencial Θ(n); sem acesso direto, sem busca binária.
  • Funções que podem mudar a cabeça retornam a nova cabeça (ou recebem No **).

6.3 Erros comuns (releia isto na véspera)

  1. Desreferenciar NULL: p->info sem ter testado p != NULL.
  2. Inverter a ordem das ligações: religar o anterior antes de ligar o novo nó ao resto → perde a lista.
  3. free cedo demais: liberar o nó e depois ler p->prox.
  4. Caminhar com a cabeça: usar l = l->prox no percurso e perder a lista.
  5. Esquecer lista = funcao(lista, ...): a função devolve a nova cabeça e ninguém guarda.
  6. Passar a estrutura por valor: push(Pilha p, ...) altera uma cópia; o original não muda.
  7. Não zerar fim quando o último elemento sai da fila encadeada.
  8. Não tratar vazia/cheia: pop em pilha vazia, dequeue em fila vazia, push em vetor cheio.
  9. Esquecer novo->prox = NULL ao criar o nó que vai ser o último — ele fica apontando para lixo.
  10. Vazamento de memória: remover sem free, ou perder o endereço antes de liberar.
  11. Misturar convenções de topo (índice × quantidade) no mesmo código.
  12. Trocar . por -> — erro de compilação fácil no computador, erro de nota fácil no papel.

6.4 Pegadinhas de prova

  • top não remove. Uma sequência de operações com top() no meio existe só para pegar quem lê rápido demais.
  • Vetor de fila circular fora de ordem. Perguntar "o conteúdo de dados[0]" é diferente de "o primeiro da fila".
  • Elementos "removidos" que continuam no vetor. O pop mexe no índice, não apaga o valor.
  • Curto-circuito do &&. Trocar a ordem de p != NULL && p->info == v quebra o programa; saber explicar por quê vale ponto.
  • Inserir na posição 0 e remover o primeiro — os casos especiais que todo mundo esquece de tratar.
  • "Qual estrutura usar?" disfarçado num enunciado em texto corrido. Procure as palavras do quadro 5.3.
  • Complexidade de insere_fim: a resposta muda conforme exista ou não um ponteiro para o fim. Diga sob qual hipótese você está respondendo.

6.5 Como acompanhar os ponteiros em uma questão escrita

Um método que funciona na hora da prova, com papel:

  1. Desenhe o estado inicial com caixas e setas, incluindo todos os ponteiros nomeados (l, p, ant, topo, inicio, fim).
  2. Execute uma linha por vez. Nunca duas.
  3. Atribuição a ponteiro = apagar uma seta e desenhar outra. Apague só a seta que sai do lado esquerdo da atribuição.
  4. Depois de cada linha, pergunte: algum nó ficou sem ninguém apontando para ele? Se ficou e não foi liberado, é vazamento — e provavelmente um erro.
  5. Ao final, confira os casos de borda: lista vazia, um único elemento, remover o primeiro, remover o último.
   Exemplo de folha de rascunho para  ant->prox = p->prox;

   antes:   ant -> [20] -> [30] -> NULL
                    p

   passo:   a seta que SAI de ant é apagada e redesenhada para p->prox

   depois:  ant ----------> [30] -> NULL
                    [20]  (sem ninguém apontando: precisa de free)

6.6 Como analisar a complexidade das operações

Roteiro de três perguntas:

  1. A operação percorre a estrutura? Se não percorre (só mexe em ponteiros/índices de uma ponta conhecida), é Θ(1). Se percorre tudo, Θ(n).
  2. Percorre até onde? Até a posição k → Θ(k), com pior caso Θ(n). Até achar um valor → Θ(n) no pior caso, Θ(1) no melhor.
  3. Há laço dentro de laço? Para cada nó, varrer o resto da lista → Θ(n²).

Lembre que Θ dá o comportamento exato (limite superior e inferior), enquanto O dá só o limite superior. Dizer que push é O(n) não é falso — é impreciso. Quando a operação tem um custo bem definido, o correto é Θ.

int pop(Pilha *p, int *saida) {
    No *aux;
    if (p->topo == NULL) return 0;    /* corrige o bug 1 */
    aux       = p->topo;
    *saida    = aux->info;
    p->topo   = aux->prox;            /* lê ANTES de liberar */
    free(aux);                         /* corrige o bug 2 */
    return 1;
}

7.5 Dez questões de revisão

  1. Defina pilha e fila como TAD, sem citar vetor nem lista ligada.
  2. Por que uma fila implementada com vetor precisa ser circular?
  3. Qual a diferença entre pop e top? E entre dequeue e frente?
  4. Por que a pilha encadeada dispensa um if para o caso "vazia" no push, mas a fila encadeada precisa de um no enqueue?
  5. Em que situação insere_fim em lista ligada é Θ(1)?
  6. Por que não faz sentido aplicar busca binária em uma lista ligada ordenada?
  7. O que acontece se, no push da pilha encadeada, você fizer p->topo = novo antes de novo->prox = p->topo?
  8. Por que a remoção em lista simplesmente ligada precisa do nó anterior?
  9. Cite duas vantagens do vetor sobre a lista ligada e duas da lista sobre o vetor.
  10. Um programa precisa guardar as últimas ações do usuário para um "desfazer" e, separadamente, as tarefas a executar por ordem de chegada. Qual estrutura para cada caso, e por quê?
Respostas resumidas
  1. Pilha: coleção com inserção e remoção na mesma extremidade; comportamento LIFO. Fila: inserção em uma extremidade e remoção na outra; comportamento FIFO. O TAD descreve as operações e as garantias, não a implementação.
  2. Porque sem a circularidade os índices só andam para a direita: as posições liberadas pelos dequeue no começo do vetor ficariam inutilizáveis e a fila se daria por cheia com espaço sobrando.
  3. pop e dequeue removem e devolvem; top e frente apenas consultam, deixando a estrutura idêntica.
  4. No push, novo->prox = p->topo funciona igualmente bem quando topo é NULL. No enqueue, a fila vazia tem fim == NULL, e f->fim->prox desreferenciaria NULL — daí o if.
  5. Quando a estrutura guarda um ponteiro para o último nó (é o caso da fila encadeada). Sem ele, é Θ(n).
  6. Porque a busca binária depende de acessar o elemento do meio em Θ(1). Na lista, chegar ao meio custa Θ(n), o que anula o ganho.
  7. novo->prox passaria a apontar para o próprio nó novo, criando um ciclo; e o resto da pilha ficaria sem ninguém apontando para ele — vazamento e possível laço infinito.
  8. Porque as setas só apontam para frente: quem precisa passar a apontar para depois do nó removido é o anterior, e não há como alcançá-lo a partir do nó removido.
  9. Vetor: acesso direto por índice em Θ(1) e nenhum gasto de memória com ponteiros. Lista: tamanho dinâmico e inserção/remoção nas pontas sem deslocar elementos.
  10. Desfazer é pilha (a última ação é a primeira a desfazer, LIFO). Tarefas por ordem de chegada é fila (FIFO).

Q2.

int dequeue(Fila *f, int *saida) {
    No *aux;
    if (f->inicio == NULL) return 0;   /* fila vazia: nada a remover */

    aux       = f->inicio;             /* guarda o nó que sai         */
    *saida    = aux->info;
    f->inicio = aux->prox;             /* início anda uma casa        */

    if (f->inicio == NULL)             /* saiu o último elemento:     */
        f->fim = NULL;                 /* fim não pode ficar pendurado*/

    free(aux);                          /* libera só depois de usar prox */
    return 1;
}

Os três pontos que valem a nota: teste de fila vazia, atualização do fim quando a fila esvazia, e free depois de ler aux->prox.

int conta_pares(No *l) {
    int n = 0;
    No *p;
    for (p = l; p != NULL; p = p->prox)
        if (p->info % 2 == 0)
            n++;
    return n;
}

Complexidade Θ(n): o laço visita cada nó exatamente uma vez e faz um trabalho constante em cada um (um resto de divisão, uma comparação e, no máximo, um incremento). Não há como fazer melhor, já que todo elemento precisa ser examinado.
